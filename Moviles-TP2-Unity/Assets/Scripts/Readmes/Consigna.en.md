## Assignment Brief

Development of a game specifically for the mobile platform that fully meets the requirements of the **Second Midterm - Practical Assignment No. 2: Mobile Development**

For the submission, at least **2 of the following 4 features** must be incorporated into the game, at the student's choice:

- **Ads:** Implementation of 2 different types of Ads:
  - **Interstitial Ads**, short ads that appear when the user completes a level or loses a life. These are not optional; they appear without any action from the user.
  - **Rewarded Ads**, ads offered to the user where, if accepted, a reward of some kind is granted (such as coins, experience, etc.). They are usually found in stores and have a cooldown.
- **Analytics:** Implement an analytics system and submit a report (no more than 3 to 5 pages, including charts) of the game showing the following:
  - Which devices the game is played on.
  - Game stability (% of crashes).
  - How far users play (how many levels they win, or how long it takes and where they lose).
  - What they spend the most money on within the game.
- **Cloud Save:** Implement a Cloud Save system for game progress (Google Play). It must save all progress periodically. In case the game application is reinstalled, and if it detects there is a cloud save, a popup must appear asking the user whether they want to continue playing with the local save or download the cloud save; this popup must also display the stats of both saves for comparison (level, coins, etc.). This decision must be remembered and the user must not be asked again during that installation.
- **Social Media:** The Facebook Plugin must be implemented along with the following features:
  - **Login**, to sign in with a Facebook user; this user must remain logged in even if the game is closed (the logged-in user must be displayed somewhere, such as in the settings menu, for example).
  - **Sharing**, to share the game score, whether for a level or a match—anything, really. This option can appear after completing the level.
  - **Logout**, the user must have the option to log out.

  > **PS:** Add the email `rm_cf@hotmail.com` on Facebook for testing.

### Game Optimizations:

- Asynchronous scene transitions.
- Use of **Sprite Atlases** for textures.
- **LOD**, use of **Frustum** and **Occlusion Culling**, depending on the case of your games.

### Clarifications:

- Pay special attention to the game's iconography: both inside the game—such as the icon, splash screen, etc.—and on the store page: screenshots, videos, achievements, etc.
- All UI must be adaptive and must not conflict with safe areas.
- Be careful with your games' Terms and Conditions once the new requirements are implemented, as you will likely need to update them.
- Pay special attention to the review times for games on Google Play and Facebook; they usually take some time before being approved or not.
